# questionnaire-design.md — 问卷设计细则（学术研究导向）

当用户还没有问卷文件时，执行本文件定义的 P-1 阶段：从研究方向到可执行问卷。设计完成的问卷直接进入 P0（问卷解析）流程。

## 触发条件

- 用户给出研究方向或主题，但没有问卷文件；
- 用户明确要求"帮我设计访谈问卷 / 访谈提纲"；
- 用户提供的问卷不符合结构要求且愿意重做。

## 设计流程（五步）

### 步骤1：研究定位（问用户，≤4 题）

用选项卡片快速确认研究定位，不超过一轮：

1. **研究主题**：一句话描述研究现象与领域（如"数据分析 Agent 在企业中的落地"）。
2. **学科视角**：信息系统 / 管理学 / HCI / 社会学 / 传播学 / 教育学 / 其他。
3. **研究类型**：
   - 描述性（这事是什么样）
   - 解释性（为什么是这样，找机制）
   - 理论构建（提出新概念或框架）
   - 评估性（某干预/工具的效果如何）
4. **成果要求**：学位论文（硕士/博士）/ 期刊论文 / 课程作业 / 咨询报告。

### 步骤2：研究问题收束（RQ 工作坊）

帮助用户把模糊的兴趣收束成可研究的问题：

- **核心研究问题 1 个，子问题 2-4 个。**
- 质量检验三规则：
  1. 不是"是否"题——"AI 有没有用"改成"AI 在哪些环节、以什么方式改变了什么"；
  2. 必须能通过访谈拿到证据——每个子问题注明"预期证据类型"（经历叙述 / 判断依据 / 对比感受 / 具体案例）；
  3. 子问题之间不重叠，合起来能覆盖核心问题。
- 改写示范：
  - 差：`企业会不会用数据分析 Agent？`
  - 好：`使用者在什么任务上把数据分析 Agent 纳入了日常工作流？纳入与放弃的边界由什么决定？`

### 步骤3：参考资料录入与分析

向用户请求三类材料（用选项卡片让用户勾选提供方式）：

| 材料 | 必要性 | 用途 |
|---|---|---|
| 核心文献 2-5 篇（理论框架来源） | 强烈建议 | 提取构念、理论维度，决定通用题的覆盖结构 |
| 行业资料 / 背景报告 | 建议 | 校准术语与情境，并入 P1 认知基线 |
| 前期材料（已有访谈、调研、导师意见） | 可选 | 避免重复提问，发现待验证假设 |

- 用户能提供：读取并提取「构念-证据」清单——每个构念需要在问卷中至少有一道题能拿到对应证据。
- 用户没有材料：启动 P1 预研流程代为检索，产出"AI 检索基线"并明确标注**需用户核对**，不得默许跳过。

### 【影响级】材料催交与超时兜底

实测教训：用户选择"我有材料，稍后给你"，但后续全程未提供——这是极常见的情况。若流程停在等材料上，研究就无法推进。

- 用户声明有材料但未提交时，**不要阻塞流程**：
  1. 把材料登记为待办项，明确写出"等你提供：{材料类型}"；
  2. 立即用预研代检推进，产出标注 `【待用户材料核对】` 的基线；
  3. 访谈可照常进行，但在第一份报告的备注中重申一次催交；
  4. 若整批访谈结束仍未收到，必须在方法说明中写明："本研究文献基线由 AI 检索生成，研究者提供的自有文献未纳入核对。"
- 用户只给关键词（选 C）时：按关键词检索，同样标注待核对，并在问卷中避免把未核实的术语当作既定构念。

### 步骤4：受访者矩阵与问卷生成

#### 角色矩阵设计（三角验证思维）

- 根据研究问题确定需要访谈的角色类型，至少覆盖两类视角：
  - 行动者（直接使用/操作的人）
  - 受影响者或协作者（被结果影响或需要接手的人）
  - 监督者/治理者（维护、审核、决策的人）
- 每类角色建议 2-4 人起步；定义饱和标准（连续 2 位受访者无新主题出现即停）。
- 输出角色矩阵表：角色 / 抽样策略 / 计划人数 / 该角色回答哪个子问题。

#### 问卷结构（与执行流程完全兼容）

```
# {研究主题}访谈（{角色}）
> 说明：知情同意与敏感豁免段（模板见 assets/questionnaire-template.md）

## 通用问题（所有人都回答）
Q1 最近一次任务（行为叙述）
Q2 问题怎样变清楚（条件与分歧）
Q3 实际怎样完成（人机分工）
Q4 如何判断结果可用（核验与决策）
Q5 工作和产出有何变化（前后对比）
Q6 局限和不同经验（边界 + 归因拆分题，固定内置）

## {角色}追问
R1-R3（每角色 3 题，深一层：拿机制、拿态度、拿改进诉求）
```

- **归因拆分题为固定内置题**（Q6 内嵌："同期的数据整理、培训、人员或流程变化，是否也影响了上述体验？"），任何问卷都不得删除。
- **题目映射表**必须随问卷一并产出（见下），这是答辩时"问卷怎么来的"的辩护证据。

#### 题目映射表（每份问卷必备，但必须与受访者版分离）

| 访谈题 | 服务的研究问题 | 对应构念/维度 | 预期证据类型 |
|---|---|---|---|
| Q1 | RQ1 | 使用情境 | 经历叙述 |
| ... | ... | ... | ... |

**【影响级】映射表等出题人信息一律输出到独立文件** `{问卷名}-出题人附页.md`，不得内嵌在受访者版问卷中——包括不要放在 HTML 注释里。

理由（实测教训）：问卷常会被直接转发、转 Word 或转 PDF 给受访者；注释、隐藏段落、附页在转换后依然可见，等于把研究假设与预期答案直接交给受访者，构成严重引导，且会污染"受访者是否知情"的伦理判断。

- 受访者版问卷只包含：说明段、通用题、角色追问题、感谢语、修订记录（修订记录可保留，属方法透明度）。
- 出题人附页独立保存，供方法章节与答辩使用。

### 步骤5：预测试（强烈建议，不可替用户跳过提醒）

- 批量访谈前，先用 1 位受访者走完整流程（P0-P4），检验三件事：题目可答性（答得上来吗）、选项覆盖率（有没有人都选不出）、时长（受访者疲劳点在哪）。
- **修订必须回流**：把修订写回问卷文件、打版本号、保留修订记录（规则见 `references/protocol.md` 的"预测试修订回流"）。只写结论不改文件等于没做预测试。
- 预测试受访者编号单独标记（如 P01），不计入正式样本。

### 两个边界情况的处理规则

- **子问题超出上限**：规定为 2-4 个，若研究者坚持加第 5 个，允许保留，但要求其指定"哪一个可以合并或降级为次要问题"，避免 RQ 失焦。
- **角色矩阵被削减**（如"管理者那组我约不到"）：允许削减，但必须在问卷或方法说明中记录"三角验证缺口"——写明本研究的结论仅由哪几类视角支撑、缺失哪一类视角、对内部效度的影响。不得静默删掉角色。

## 题目措辞规范（学术半结构访谈）

1. **行为化**："请讲一次最近……"优于"你觉得……"——拿经历不拿观点。
2. **时间锚点**："大致时期即可"，降低回忆负担。
3. **例子邀请**：括号内给 2-4 个示例并声明"不限于此"。
4. **敏感豁免**：题内或说明段写明"可不提供名称与数字，用概括说法"。
5. **一题一事**：禁止复合提问（"你怎么用以及为什么"拆成两题）。
6. **非诱导**：不暗示期望答案（避免"你是否也遇到过很不好用的情况"）。
7. **分层设计**：通用题拿事实与行为，追问题拿机制、态度与边界——追问题必须引用通用题的回答（"接着你刚才说的那次……"）。

## 与后续阶段的衔接

- 问卷定稿后按角色分别输出 `访谈题目_{角色}.md`（格式同 `assets/questionnaire-template.md`），即可逐位进入 P0-P5 流程。
- 问卷的「构念-证据」清单保留至分析阶段：跨案例矩阵的对比维度优先从构念清单中选取，保证"问的就是要研究的"。
