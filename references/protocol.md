# protocol.md — 分阶段实施细则

## P0 问卷解析与编号管理

### 问卷解析
- 通读问卷全文，标记三类题目：
  - **通用题**（通常 Q1-Q6）：所有角色共用，协议完全一致以保证可比性。
  - **角色追问题**（如使用者 U1-U3 / 维护者 M1-M3 / 审核者 R1-R3）：随角色变化，是本批访谈的差异化数据来源。
  - **固定内嵌题**：如"同期变化 / 与刚才解释不一致"类，属于归因拆分题，必须保留。
- 若问卷缺少归因拆分题，在 Q6 或末题后主动补一题："同期还有哪些变化影响了你的体验？"

### 【体验级】伦理与知情同意提醒

面向学位论文、期刊论文等正式研究时，P0 必须主动提醒研究者（不替其决定）：

- 涉及人类受试者的访谈通常需经所在机构伦理审查（IRB／伦理委员会），或确认适用豁免流程。
- 需要一份书面/口头的知情同意说明（研究目的、数据用途、退出权、匿名化方式），可基于 `assets/briefing-template.md` 扩展。
- 录音/转写、引文使用范围需事先取得受访者同意。
- 提醒一次即可，不要反复打断流程；研究者明确表示不需要时记录"研究者已确认豁免"。

### 编号管理
- 成稿前先扫描产出目录：列出已有受访者编号与角色。
- 新受访者取最大编号 +1；发现用户提供编号与已有冲突时，提出改号建议，经确认后执行：全文替换编号 + 文件重命名 + 同步更新对比矩阵中的列名。
- 同一研究的多角色系列建议在编号后标注角色（如"06号·维护者"），便于矩阵管理。

### 访谈须知要素（基于 assets/briefing-template.md）
- 自愿、可跳过、可随时停止。
- 不要求敏感信息（内部报告、客户名、经营数字、口径公式），用概括说法。
- 流程预告：先 4 个定位问题，再逐题进行；每题给选项，但"用自己的话描述质量最高"。
- 编号匿名，引用范围会与受访者核对。

## P1 领域预研细则

### 检索轮次（2-4 轮，按角色调整）
| 轮次 | 内容 | 产出 |
|---|---|---|
| 1 | 主题行业现状与演进阶段 | 行业走到哪一步、验收标准是什么 |
| 2 | 公认局限与失败模式 | 可直接用于 Q4/Q6/追问的素材 |
| 3 | 人机分工共识与信任/核验行为研究 | 可用于 Q3/Q5/追问的分工边界 |
| 4 | 受访者角色特有工作内容（新角色必做） | 角色基线：职责、机制、痛点、行业叫法 |

### 认知基线输出要求
- 控制在 5 个要点以内，每条 1-3 行，附关键数据或结论。
- 明确标注信息时点（如"2026 年公开资料"）。
- 基线是给研究者看的"共用弹药"，不直接塞给受访者，避免引导。

### 【阻断级】基线必须可追溯，未确认不得进入报告

实测教训：报告中写"某研究指出……"却没有作者、年份、标题、链接，研究者无从核对；若引用有误即构成学术不端风险，而责任在研究者。

- **基线必须落盘为独立文件**（如 `{主题}-认知基线-YYYY-MM-DD.md`），与访谈报告同目录，供研究者随时调阅。
- **每条基线必须带完整出处**：作者/机构、年份、标题、链接或 DOI；只有结论无出处的条目**不得写入任何报告的对照表**。
- **设置确认门**：基线首次产出后须请研究者确认（哪怕是"我大致看过"）。未确认前，报告中涉及基线的段落一律标注 `【基线未核对】`。
- 若研究者提供了自己的文献（P-1 步骤 3），基线优先以研究者材料为准，AI 检索部分降级为补充并标注来源。

### 角色切换规则
- 使用者 → 维护者 → 审核者等角色切换时，重新执行 P1 的角色侧检索（第 4 轮必须重做）。
- 主题侧基线（第 1-3 轮）可复用，在报告中注明"与前期报告共用同一套基线"。

## P2 锚点定位细则

固定四问（选项可按研究主题调整措辞，维度不可缺）：
1. **角色定位**：决定叙述视角（业务使用者 / 分析岗 / 管理者 / 使用者兼建设者 / 维护者 owner）。
2. **典型任务场景**：决定 Q1 的故事类型（异常诊断 / 周期报告 / 漏斗分析 / 口径校验 / 错题处理）。
3. **工具或系统形态**：决定 Q3 的流程描述（企业 BI 内置 / 通用大模型+文件 / 自研工作流 / 混用）。
4. **行业领域**：决定合规、口径、数据源等背景约束。

锚点回答后必须复述画像（一句话），例如："你是纯业务侧使用者，被动响应型，多工具混用"——确认后再进入 Q1。复述不准时当场修正。

## P3 分批访谈细则

### 分轮节奏
- 每轮 ≤4 题（选项工具的实际上限），按 Q1-Q2 / Q3-Q4 / Q5-Q6 / 角色追问分轮。
- 每轮开头先给 1-3 句**草稿预填**，再给选项卡片。草稿预填要敢于"猜错"——受访者的纠正本身就是数据。
- 轮与轮之间用一句话串联受访者的关键回答（"你刚才说 X，这跟你这一轮的选择正好呼应/冲突"）。

### 追问触发器（出现以下信号必须追问）
- 回答与认知基线明显偏离（如行业说"以业务为准"，受访者说"数据团队内部定"）。
- 前后回答存在张力（如"在乎普遍性"vs"只验证个例"）。
- 受访者使用了自己的独特说法（如"从一问一答变成产品服务"）——原话记录，追问其含义。
- 受访者选择了"负面选项"——追问一个具体例子。

### 【影响级】跨轮一致性检查（每轮结束必做，不是碰运气）

实测教训：最有价值的一段材料来自"矛盾追问"，但矛盾是偶然被发现的。必须把发现机制变成流程：

每轮回收答案后，固定做一次三项检查，再进入下一轮——
1. **前后一致性**：本轮答案与此前各轮是否存在张力？
2. **跨角色一致性**（若已有其他角色受访者）：本轮答案与另一侧角色的说法是否冲突或互证？
3. **与基线一致性**：本轮答案与认知基线的行业共性是否明显偏离？

任一命中即当场追问（题干模板："你前面说 X，这里又说 Y，这两句放在一起有点拧——到底是哪一个？"），并把回应完整写入报告的"矛盾回应"小节。**整批访谈结束时的检查不算数，必须当场问。**

**【影响级】检查必须留痕，不能只靠自觉**：每轮访谈输出时，附带一张「一致性检查卡」，作为该轮的强制产物随记录保存：

```
【一致性检查卡 · 第 N 轮】
1 前后一致性：无张力 / 有张力 → 已追问（写清哪两句）
2 跨角色一致性：无对话对象 / 无张力 / 有张力 → 已追问
3 与基线一致性：无偏离 / 有偏离 → 已追问
```

未产出该卡即视为该轮流程未完成。实测教训：一致性检查写了规则但执行靠自觉，仍会被跳过；变成可见产物后才可审计。

### 【影响级】证据效力分级：草稿全盘点头时，把重心移到追问

实测教训（01 号）：该受访者全程对草稿答"草稿没问题"，全稿最有价值的原话**几乎全部来自两道追问**（跨角色对照、一致性追问），主答题只起到定位作用。根因是草稿预填把"从零写"变成了"点头"——**点头不产出语言**。

**证据效力三级**（成稿与引用按此排序）：

| 级别 | 来源 | 用途 |
|---|---|---|
| 1（最高） | `【原话】`：自发陈述、追问回应、自由输入 | 论文引语只从这里取 |
| 2 | 选项确认（锚定事实） | 定位与跨案例可比，不作引语 |
| 3（最低） | `【确认草稿】`：含"草稿没问题" | 只作背景，不升级为原话 |

**重心转移规则（当场执行，不得延到成稿后）**：

- **触发条件**：同一受访者连续 2 轮对草稿答"草稿没问题"，且无自定义补充、未命中任何追问触发器。
- **判定**：该场访谈的主答题已退化为"只产出定位、不产出原话"。
- **处置**：
  1. 主答题提速——选项只作定位记录，不再在其上展开；
  2. 时间投向三类追问：① 一致性/矛盾追问（见上节）；② 跨角色或跨案例对照追问（把另一侧的说法转述给本人："另一位受访者说 X，你怎么看？"）；③ 具体事件追问（"能讲一次具体的经历吗？当时你怎么做的？"）；
  3. 每题后固定追加一句"有没有跟这个不一样的地方"；
  4. 整场结束仍缺 `【原话】` 时，效度备注须写明"本稿以确认草稿为主，建议补充一轮自由追访"。

**协议级推论**：主答题是定位仪器，追问才是原话的主仪器。设计问卷时不得把核心构念的证据全数寄托在通用题上——追问题必须承接通用题的回答（见 `references/questionnaire-design.md` 的分层设计要求）。

### 记录规范
- 每轮结束在内部记录：锚定事实（选项选择）+ 原话金句（自由输入）+ 待验证张力。
- 区分两类数据：**选项确认**（受访者选了哪个）与**自发陈述**（受访者自己说的），成稿时自发陈述优先引用。
- **每场访谈结束时统计一次 `【原话】` 条数**，写入效度备注；过少即按上节处置，不等到写论文时才发现。

## P4 成稿细则

### 【阻断级】引文来源三分类标记

实测教训：草稿预填机制下，受访者常以"草稿没问题"确认 AI 预写的一段话。若成稿不区分，那些漂亮引文本质是 AI 写的、从未被受访者"说出"过——用于学位论文引用将构成严重效度问题，答辩无法解释。

成稿中每一段实质性陈述必须带来源标记，三选一：

| 标记 | 含义 | 可否用于论文直接引用 |
|---|---|---|
| `【原话】` | 受访者自由陈述、未经过草稿引导的原句 | ✅ 可以 |
| `【确认草稿】` | AI 预写、受访者明确确认或修正后的内容 | ⚠️ 仅可用于内容编码，引用需注明"经受访者确认的表述" |
| `【转述】` | 研究者中转、AI 归纳后的表述 | ❌ 不得作为引语，仅作背景说明 |

- **"草稿没问题"默认标记为 `【确认草稿】`，不升级为 `【原话】`。**
- 报告末尾的"可直接引用的原话"清单，**只允许收录 `【原话】` 条目**。
- 若某位受访者全稿几乎没有 `【原话】`，必须在效度备注中写明"本稿以确认草稿为主，建议补充一轮自由追访"。

### 成稿结构
- 元信息头（编号 / 日期 / 角色 / 工具或系统 / 任务 / 行业）→ 通用题作答 → 角色追问题作答 → 矛盾回应（如有）→ 附：作答备注。
- 文风：口语化第一人称，保留犹疑、限定与自我校正（"说实话""这里有个张力"），不润色成商务腔。

## 【影响级】预测试修订回流

预测试的目的不只是验证，更是要**改题**。实测教训：预测试结论已写明"Q4 应改为多选"，但问卷文件原封未动，下一位受访者拿到的仍是旧题。

- 预测试结束后必须产出**修订清单**：题号 / 问题 / 修改动作 / 是否影响已访谈者。
- 修订必须**写回问卷文件**，并在文件头打版本号（如 `v1.1（2026-10-11 预测试后修订）`）。
- 修订记录保留在问卷文件末尾，供论文方法章节引用。
- 若修订影响已完成的受访者作答（如新增题目），需标注"该题为 P01 之后新增，前序样本缺失"。

## 常见翻车点（经验教训）

1. 选项写成"正确的废话"（如"提高效率/降低成本"），受访者无法指认，全部全选，信息量为零。
2. 草稿预填太圆滑，不得罪人也不具体，受访者无从纠正。
3. 一口气把 9 题全抛出去，受访者疲劳，后三题质量塌掉。
4. 发现矛盾但不好意思追问，错失全文最有价值的段落。
5. 成稿时把受访者的口语润色成书面腔，丢失质性研究需要的"在场感"。
