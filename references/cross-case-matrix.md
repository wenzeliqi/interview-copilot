# cross-case-matrix.md — 跨案例对比矩阵累积规则

跨案例矩阵是本技能区别于单次访谈的核心资产：每新增一位受访者，矩阵扩展一列，共性与分歧动态更新。

## 矩阵结构

### 主表：维度 × 受访者

| 对比维度 | 01号 | 02号 | ... | N号 |
|---|---|---|---|---|
| 角色 | | | | |
| 任务性质 | | | | |
| 触发方式 | | | | |
| 工具形态 | | | | |
| 起始清晰度 | | | | |
| 头号卡点 | | | | |
| 分歧处理 | | | | |
| 信任建立方式 | | | | |
| 采用情况 | | | | |
| 拍板人 | | | | |
| 工作变化 | | | | |

| 优先改善 | | | | |

维度列表可按研究主题增删，但**同一批受访者必须共用同一套维度**，且新维度加入时需回填既有受访者的答案（从既有报告中提取，提取不到标"未覆盖"）。

### 共性区：结构性发现

- 入选标准：≥2 位受访者独立成立的表述。
- 写法：一句话结论 + 证据分布（哪几人、他们各自怎么说的）。
- 强度排序：把"全员成立"的排在最前。
- 已验证的高价值共性句式（来自首批实践，供参照，不要照抄）：
  - "数可信、解读/意义不可信"——受访者保留数、修改或重做结论。
  - "信任靠外部对照，不靠过程追溯"——与厂商"可溯源"卖点形成错位。
  - "转交成本落在意图与意义，不在数据"。
  - "所有人都主动做了归因拆分，无人把体验变化全归功于工具"。

### 分歧区：调节因素

- 入选标准：受访者之间存在系统性差异，且差异能被某个变量解释（角色、是否参与建设、治理成熟度、任务性质）。
- 写法：差异现象 + 解释变量 + 机制猜测（标注"待更多案例验证"）。
- 已验证的高价值分歧模式（供参照）：
  - "采用程度与口径治理水平成反比"（治理越好，对解读期望越高，解读对不上时信任崩得越快）。
  - "卡点位置随使用者位置阶梯式上移"（可达性 → 判断 → 解释 → 资产化）。
  - "口径最终解释权的权力结构差异"（自己拍 / 业务为准 / 数据团队为准 / 团队评审）。

### 镜像对照区（跨角色时启用）

当受访者包含不同角色（如使用者 + 维护者），建立镜像表：

| 角色 A 说了什么 | 角色 B 对应的现实 | 含义 |
|---|---|---|

镜像互证（两位互不相识的受访者描述了同一件事的两面）是全部证据中强度最高的，必须单独标注。示例：使用者说"数据团队从一问一答变成产品服务" ↔ 维护者说"我从响应需求变成经营系统"。

## 累积操作规则

1. 每完成一位新受访者：主表加一列 → 更新共性区（新成立的升级、被动摇的降级）→ 更新分歧区 → 检查是否出现新的镜像对。
2. 共性表述被新案例**削弱**时，不删除，改为标注成立范围（如"在使用者中成立，维护者中不成立"）——边界化的发现比推翻更有价值。
3. 每份新报告只放**截至当前的完整矩阵**，保证任何一份报告独立可读。
4. 达到 5-6 位受访者时，主动建议用户生成独立的跨案例分析文档，作为论文分析章节的骨架。

## 给研究者的追问建议区

每份报告末尾保留"建议追问的点"（2-4 条），来源：
- 该受访者回答中未展开的高价值细节；
- 与基线或其他受访者矛盾、但本场未及追问的点；
- 可在后续受访者中**固定化**的追问（一旦某追问在两人以上身上产出好数据，升级为协议固定题）。
