# 访谈副驾驶 · 学术质性研究版（Interview Copilot）

![License: CC BY 4.0](https://img.shields.io/badge/License-CC%20BY%204.0-lightgrey.svg) ![Version](https://img.shields.io/badge/version-1.4.0-blue) ![Agent Skills](https://img.shields.io/badge/format-Agent%20Skills-green)

> 研究者主导、AI 辅助的结构化深度访谈技能，面向论文质性访谈、专家访谈、组织诊断与咨询尽调。
> 让专家访谈具备"批量化研究"的能力：受访者只点选项，AI 干重活。

## 这是什么

一个 WorkBuddy 技能（skill），覆盖"从研究想法到跨案例矩阵"的完整链路：

```
无问卷时：研究定位 → 研究问题收束 → 参考资料分析 → 角色矩阵 → 生成问卷（可预测试）
                ↓
有问卷后：读问卷 → 行业预研 → 锚点定位 → 逐题访谈（选项卡片）→ 第一人称成稿 → 跨案例矩阵
```

**还没有问卷也能开始**：告诉它你的研究方向，它会通过几轮选项对话帮你把研究问题收束清楚、分析你的参考文献、设计受访者角色矩阵，最后产出可以直接开访的问卷文件——每道题都带着"服务哪个研究问题"的映射表，答辩时这就是"问卷怎么来的"的辩护证据。

你（研究者）只需要：把访谈问卷文件交给它，然后把受访者"请到屏幕前"。
受访者只需要：看草稿、点选项、偶尔补一两句自己的话。

**它和你熟悉的工具不一样的地方**：

| | 传统人工访谈 | AI 访谈平台（Outset 等） | 本技能 |
|---|---|---|---|
| 谁主持 | 你 | AI（你不在场） | 你主持，AI 当副驾驶 |
| 受访者负担 | 全程口述/打字 | 语音/视频对话 | 点选项为主 |
| 访谈前预研 | 你自己做 | 无 | AI 自动做，建成认知基线 |
| 跨案例对比 | 手工整理 | 按项目隔离 | 自动累积成矩阵 |
| 适合场景 | 深度但难批量 | 规模化消费者研究 | 论文/专家/组织访谈（几人~几十人） |

## 适合谁

- 写毕业论文，需要做 5-20 场专家/用户访谈的研究生
- 做组织诊断、员工访谈、多角色利益相关方研究的研究者
- 做咨询尽调、行业专家访谈的顾问
- 任何需要"同一套问题问很多人、最后做跨案例分析"的场景

**不适合**：民族志、需要长期建立信任的深访、情感强度高的敏感话题——这些场景里人的在场不可替代。

## 快速开始

### 还没有问卷（从研究想法起步）

> 「我想研究 XX 领域，需要设计访谈问卷，还没成型。」

它会先和你确认研究定位（主题/学科视角/研究类型/成果要求），帮你把研究问题收束成"核心 RQ + 子问题"，请你录入参考文献（没有的话它代检并标注需你核对），然后设计受访者角色矩阵，最后按角色各产出一份问卷文件 + 题目映射表。建议接着做 1 位预测试再批量访谈。

### 第一位受访者

> 「这是我的访谈问卷 `@访谈题目.md`，帮我按流程访谈，编号 01。」

它会自动：解析问卷 → 做行业预研并给你一份认知基线 → 生成访谈须知（你转给受访者）→ 开始逐题访谈。

### 后续受访者

> 「02号坐下了，继续。」

它沿用完全相同的协议（保证可比），访谈结束后自动把跨案例对比矩阵扩展一列。

### 换角色（问卷有多个版本）

> 「接下来是维护者问卷 `@访谈题目_维护者.md`，先做这个角色的背景研究再开始。」

它会针对新角色重新做预研（使用者、维护者、审核者各有各的基线），并在报告中自动生成"镜像对照"（使用者抱怨的 ↔ 维护者每天在修的）。

### 受访者的体验长这样

每轮访谈，受访者看到的是：

1. **一段草稿**（AI 基于行业共性 + 他的定位猜的答案）——"对"就确认，"不对"就纠正；
2. **四个选项**（每个都是一个完整立场，含"负面选项"）——点一个即可；
3. 也可以完全不理会选项，**直接用自己的话说**（这种回答最值钱）。

一位受访者的全程耗时大约是纯文字访谈的 1/3。

## 你会得到什么

每位受访者产出一份 `{编号}-{主题}访谈-{日期}.md`：

- **元信息头**：编号、角色、工具、任务、行业（便于统计）
- **第一人称作答稿**：口语化、保留犹疑和自我校正的原文感
- **跨案例对比矩阵**：截至当前所有人的主表 + 共性发现 + 分歧因素
- **作答备注**（给研究者）：建议追问的点、行业基线对照（可直接支撑论文）

做到 5-6 人时，矩阵会自然浮现结构性发现（共性）和调节因素（分歧），那就是你论文分析章节的骨架。

## 使用技巧

- **给问卷文件，别贴正文**：用 `@文件路径` 引用问卷，它能解析"通用题 + 角色追问题"的结构。
- **编号让它自己管**：它会先扫描目录里已有的编号，冲突时自动顺延（比如 04 被占了就改 06）。
- **受访者说"都不对"时别慌**：那是最好的数据，它会原话记录并追问。
- **关键引语要回收确认**：成稿后把要引用的段落发给受访者核对原文（方法论要求，见下）。

## 方法论声明（写论文前请读）

本方法的定位是"选项卡片式探针访谈"，介于问卷与深访之间。`references/validity-notes.md` 里有完整的效度说明和答辩预案，三条底线：

1. 选项是探针不是答案，受访者的自发陈述优先于选项确认；
2. 答案经研究者中转，关键引语需受访者原文核对后再引用；
3. 受访者自愿、匿名编号、引用范围需与其核对；
4. **草稿预填的文字不等于受访者原话**：成稿会标注 `【原话】/【确认草稿】/【转述】`，论文引语只取 `【原话】`；"草稿没问题"不算原话；
5. **预研检索的文献基线必须你自己核对**：基线会单独落盘并带完整出处，未经你确认的条目不会进入结论性对照表。

> v1.2 说明：这两条来自一次真实压测中用户提出的尖锐反馈——AI 预写草稿可能变成"未经察觉的伪造引文"，未核实的检索基线可能变成学术不端风险。二者均已内置为强制规则。

## 免责声明与责任约定

**本技能是研究方法工具，不是研究合规的承担者。**

它能把访谈执行的质量从 60 分提到 85 分，但**研究伦理与学术合规的最终责任始终在使用者（研究者）本人**。它可以提醒、可以内置检查项、可以拒绝替你作决定，但不能替你完成合规动作，也不承担相应后果。

### 责任分工表

| 事项 | 本技能负责 | 你（研究者）负责 |
|---|---|---|
| 伦理审查（IRB / 伦理委员会） | 识别并提示需审查的场景 | 判断是否需要、提交申请、获批后开展 |
| 知情同意 | 生成须知与同意要素模板 | 确认内容合规，取得并保存同意记录 |
| 匿名化与数据处理 | 默认编号匿名、不采集敏感信息 | 决定存储位置、访问权限、保存期限与销毁方式 |
| 文献与基线核查 | 基线单独落盘，每条带完整出处 | 逐条核对原文；未核对条目不得进入论文 |
| 引语真实性 | 三分类标记 `【原话】/【确认草稿】/【转述】` | 关键引语回收受访者确认；论文只引 `【原话】` |
| 弱势群体保护（未成年人、患者、下属等） | 提示需额外保护措施 | 落实监护人同意、避免权力不对等施压等 |
| 数据安全 | 不发起任何网络请求，产出写入你指定的本地目录 | 产出文件的保管、备份、脱敏与合规传输 |

### 免责条款

1. **产出物为中间件**：问卷、认知基线、草稿预填、成稿、跨案例矩阵均为待核验的研究材料，不是可直接提交的成果。未经研究者核对即进入论文，责任由研究者承担。
2. **不阻断研究者决定**：本技能在伦理相关节点**必须发出提醒**，但**不阻断**你的决定——你是研究的最终决策者，AI 只做提示，不做裁判。
3. **不提供专业意见**：本技能不提供法律意见、伦理审查结论或学术合规判定。涉及人体受试者、个人隐私数据、跨境数据流动等，请咨询所在机构的伦理委员会与法务。
4. **引文风险自负**：草稿预填的文字若未经验证被当作受访者原话引用，构成学术不端风险；本协议已内置标记机制降低该风险，但核实义务在使用者。
5. **数据不托管**：技能本身不持有、不上传、不同步任何研究数据；数据全生命周期的安全由使用者负责。

> 首次使用时，它会向你一次性呈现上述责任清单。你可以直接开始——但这份清单的每一项，都请在正式采集前自己过一遍。

## FAQ

**Q：受访者可以自己对着电脑做吗，需要我在场吗？**
A：都可以。你在场时它当你的副驾驶；你不在场时，把会话链接给受访者自己做也行，但关键引语事后要回收确认。

**Q：我有自己的问卷，能直接用吗？**
A：能。它会自动识别"通用题 + 追问题"结构；如果没有"归因拆分题"，它会建议补一题。

**Q：没有问卷，只有一个研究方向呢？**
A：这正是它的入口之一。它不会直接甩给你一份问卷，而是先帮你把研究问题收束清楚、分析你的文献、定好受访者矩阵，再生成问卷——生成的问卷每一题都能追溯到研究问题。

**Q：访谈能做到一半换人吗？**
A：能。协议是无状态的，报编号和角色就能继续。

**Q：数据会被上传吗？**
A：产出文件写在你指定的本地目录。`SKILL.md` 与 `references/` 均为纯 Markdown，不含任何可执行代码、脚本或自动网络请求（已通过安全审计，P2 级）。README 与 SKILL.md 中的链接仅供人阅读与反馈，技能执行时不会访问。

**Q：我能商用吗？能改成自己的版本发布吗？**
A：CC BY 4.0 下两者都可以，包括商用。唯一条件是保留署名并标明修改。建议 fork 后保留 `CHANGELOG.md` 与规则出处——那些出处是这套规则的证据链，删掉后别人无法判断某条规则还该不该信。

**Q：这个方法论和我论文的关系？**
A：它是方法工具，不是研究发现。上传 GitHub 不视为预发表（通常不影响期刊投稿），且提交记录可作为"在先公开"的时间戳证据。若期刊对材料公开有特殊要求，请以期刊规定为准。
